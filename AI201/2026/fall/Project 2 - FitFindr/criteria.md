# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
My search uses keyword and substring matching against listing titles and descriptions. Some user queries might use synonyms or phrasing that misses the exact keywords in our dataset, so 4 of 5 allows for search heuristic misses while still ensuring the core pipeline succeeds on valid matches.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
This is a purely deterministic branch rule in Python (`if not session["listings"]:`). Because there is no LLM randomness involved in checking an empty list, the agent should correctly halt before calling downstream tools every single time (5 of 5).

---

## 3. Selected item ID matches across all session state transitions

Given a query that finds matching listings, the `id` of `session["selected_item"]` matches the item ID passed into `suggest_outfit` and `create_fit_card` in 5 of 5 tries.

**Why this target:**
Passing state through the session dictionary is deterministic Python logic. If the selected item changes or gets lost between tool calls, it means the state management in the planning loop is broken, so this must work in 5 of 5 tries.

---

## 4. Fit card includes price, platform, and proper length

Given a generated outfit suggestion, the resulting fit card caption is between 2 and 4 sentences long and explicitly mentions the item's price and platform in at least 4 of 5 tries.

**Why this target:**
The fit card is generated by an LLM with non-zero temperature, so the phrasing will naturally vary. While the prompt explicitly instructs the model to include the price, platform, and keep it concise, LLM output can occasionally drop a detail, so 4 of 5 is a realistic and measurable quality bar.

---

## 5. Graceful styling advice on empty wardrobe

Given a query with an empty wardrobe (`wardrobe["items"] == []`), the agent completes the run and `suggest_outfit` produces general styling ideas without raising an exception or hallucinating owned items — in 5 of 5 tries.

**Why this target:**
Detecting an empty wardrobe is an explicit conditional check in `suggest_outfit`. The tool should cleanly branch to a general styling prompt rather than crashing or inventing nonexistent closet pieces, making 5 of 5 an achievable and important target.
